# Project Instructions for AI Agents

This file provides instructions and context for AI coding agents working on this project.

## What This Is

Go language bindings for the [wolfSSL](https://www.wolfssl.com/) C cryptography library. A single package (`wolfSSL`) wraps wolfSSL's `wc_*` wolfcrypt API and its TLS/SSL layer via CGO. Callers get wolfSSL's performance-optimized crypto under a thin Go-idiomatic surface.

Upstream: `github.com/wolfssl/go-wolfssl`

## External Dependencies

| Dependency | Location | Notes |
|---|---|---|
| wolfSSL C library | `~/wolfssl` or system install | Must be **built and installed**; headers in `/usr/local/include/wolfssl/`, lib in `/usr/local/lib/` |

CGO header/library paths are declared at the top of each `.go` file:
```c
// #cgo CFLAGS: -I/usr/include -I/usr/include/wolfssl -I/usr/local/include -I/usr/local/include/wolfssl
// #cgo LDFLAGS: -L/usr/local/lib -lwolfssl
```
For a non-standard wolfSSL installation, adjust these paths in the relevant source files.

## Build & Test

### 1. Build and install wolfSSL

```bash
cd ~/wolfssl
./autogen.sh
./configure --enable-all --enable-opensslall --enable-opensslextra
make -j$(nproc)
sudo make install
```

### 2. Sync build options

```bash
./generateOptions.sh   # reads wolfssl/options.h → generates options.go
```

Re-run this whenever wolfSSL's `./configure` flags change. `options.go` is git-ignored.

### 3. Build the library

```bash
go build .
```

### 4. Build examples

```bash
cd examples/<subdir> && go build <file>.go
```

### 5. Integration tests (CI-style)

There are no `go test` unit tests. Correctness is verified by:
- Building and running the example programs (server + client exercises a real TLS handshake)
- GitHub Actions workflows in `.github/workflows/`: `build.yml`, `lint.yml`, `test-tls.yml`

To replicate CI locally:
```bash
go vet ./...

# TLS handshake smoke test
go build -o /tmp/tls-server examples/server/server-tls.go
go build -o /tmp/tls-client examples/client/client-tls.go
/tmp/tls-server &
sleep 0.5
/tmp/tls-client
kill %1
```

## Architecture

```
Go caller
    |
    | CGO
    v
wolfSSL package (github.com/wolfssl/go-wolfssl)
    aes.go         AES-CBC, AES-GCM, PBKDF2
    blake2.go      BLAKE2s (hash + HMAC variant)
    chacha_poly.go ChaCha20-Poly1305, XChaCha20-Poly1305 (AEAD)
    curve25519.go  Curve25519 ECDH
    ecc.go         ECC (sign, verify, ECDH, key import/export)
    fips.go        FIPS mode control and callbacks
    hash.go        One-shot: MD5, SHA-1, SHA-256/384/512
    hmac.go        HMAC (streaming), HKDF
    misc.go        ConstantCompare, zeroMemory
    random.go      WC_RNG init/free/generate
    sha.go         SHA-256 streaming (Init/Update/Final/Free)
    ssl.go         TLS/SSL context + connection (WOLFSSL_CTX, WOLFSSL)
    x509.go        X.509 store, load, verify, pubkey extraction
    options.go     (generated) build-option constants from wolfssl/options.h
    |
    v
libwolfssl.so  (/usr/local/lib/libwolfssl.so)
```

All bindings live in a **single flat package** — no subpackages.

## Conventions & Patterns

### Function naming

| Prefix | Layer | Example |
|---|---|---|
| `Wc_` | wolfcrypt (symmetric, hash, public key) | `Wc_AesGcmEncrypt`, `Wc_Sha256Update` |
| `WolfSSL_` | TLS/SSL layer | `WolfSSL_CTX_new`, `WolfSSL_connect` |
| `wolfSSL_` | OpenSSL-compat layer (x509.go) | `wolfSSL_X509_load_certificate_buffer` |
| `X509_` | OpenSSL-compat X.509 store | `X509_STORE_new`, `X509_verify_cert` |

### Return code convention

wolfcrypt functions: **0 = success**, negative = error code.
TLS functions: **`WOLFSSL_SUCCESS` (1) = success**, negative/zero = error.

Do not conflate the two. Check the specific API's convention before writing error-handling code.

### Conditional compilation

Every `.go` file includes C preprocessor `#else` stubs that return `-174` or `NULL` when a wolfSSL feature is compiled out (`NO_AES`, `NO_PSK`, `WOLFSSL_DTLS`, etc.). When adding a new wrapped function, always add the corresponding disabled-feature stub.

### Type aliases

Go types are direct aliases of C structs:
```go
type Aes = C.struct_Aes
type WC_RNG = C.struct_WC_RNG
type WOLFSSL = C.struct_WOLFSSL
// etc.
```
These are passed as pointers through the API; callers are responsible for calling the matching `Free` function.

### Aligned allocation

Some structs require SSE-aligned memory (`Wc_HmacAllocAligned`, `Wc_AesAllocAligned`). Use these variants whenever the wolfSSL function takes a heap-allocated struct.

### options.go

`options.go` is generated by `generateOptions.sh` and git-ignored. It exposes build-option constants so Go code can conditionally enable features at compile time. Never edit it by hand; regenerate from `wolfssl/options.h`.

## Test Design Constraint

There are currently no `go test` unit tests in this repository. When adding tests:

- **Never use the code under test as its own oracle.** A test that encrypts with `Wc_AesGcmEncrypt` and decrypts with `Wc_AesGcmDecrypt` proves nothing about correctness.
- Use independent oracles: NIST SP 800-38D vectors (AES-GCM), RFC 7539 vectors (ChaCha20-Poly1305), FIPS 180-4 (SHA), RFC 4231 (HMAC), RFC 7748 (X25519).
- Hardcode expected outputs as `[]byte` literals. Tests must be fully offline.

## Upstream PR Workflow

This repo is a wolfSSL project (`github.com/wolfssl/go-wolfssl`). PRs go to upstream, not to a fork.

Pre-push checklist:
```bash
go vet ./...
go build ./...
go build ./examples/...
```
